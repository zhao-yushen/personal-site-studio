# 发布与访问

仅当前任务涉及发布、更新线上站点或修改受众时读取。纯内容或设计任务不需要重新注册站点、变更权限或创建定时任务。

## 选择当前提供方

现有项目优先沿用其托管方式、站点 ID、构建配置与域名。用户指定提供方时按其要求处理。发布新版本前完成实现和对应验证；仅改变访问策略时直接查询并修改策略，不进入构建流程。

有可用的提供方工具或 hosting skill 时读取其当前指引并使用原生操作。发布授权与确认规则来自当前用户请求和提供方，而不是本 skill 固定规定。

使用 Sites 时，读取 `.openai/hosting.json` 并复用已存在的 `project_id`；不要创建替代 Site。只有一个负责人操作其 checkout 和原生工具。使用当前 Sites hosting skill 的保存、源推送、打包与部署流程，不在此复制易过时的命令和工具 schema。

## 内容与访问分开处理

发布新版本通常保留当前受众。用户明确要求公开网址时，查询现有站点能力，使用原生访问更新操作设置 public，并重新查询确认；已部署的同一版本不必为权限变更再次构建和部署。

访问授权不等于编辑权限。只修改用户要求的受众，不扩大编辑者、邀请名单或群组。保护个人材料的展示范围，不将素材目录、原始研究数据或 QA 附件自动打包到站点。

## 部署与故障恢复

源码推送状态、用于构建的源码和上传归档必须一致。版本和部署 ID 从工具结果取得。操作失败时先定位已经完成的阶段；可复用的已保存版本、归档和部署不再重复创建。

如果本机打包被环境依赖阻断，先查看提供方已有的原生兼容 helper。确有安全替代路径时只重做失败的打包阶段：检查绝对输出路径处于预期临时目录，使用新的 staging 目录，并核对归档与已保存源码的产物一致。不要为普通静态发布默认安装系统级工具或更换托管平台。

网络和部署凭据仅留在短期会话内，通过提供方支持的隐藏输入传递；不写进源码、日志、归档或 shell 参数。归档保留该版本需要的运行时元数据，排除无关原始材料。

有明确部署 ID 的非终态结果才继续查询同一部署状态。已经保存的版本按对应 ID 恢复部署，避免重复保存。终态失败且无可执行的修复时停止外部重试，保留本地结果并报告具体失败。

成功以提供方状态和返回的可用 URL 为依据。额外线上浏览只在实际功能检查需要且符合该平台规则时执行。交付成功 URL 与当前访问范围；固定个人站不自动配置更新计划。
