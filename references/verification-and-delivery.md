# 验证与交付

## 按本次改动决定检查

先写出几个能观察结果的验收条件，例如“返回案例后仍是当前作品”“暂停动态时检索完整可见”。已有结果在输入与代码未变时复用。

| 本轮改动 | 有价值的验证 |
| --- | --- |
| 文案或材料切片 | 事实、公开范围、图片语义和实际排版 |
| 大面积布局 | 代表性桌面尺寸、较小可用高度、内容长短与横向溢出 |
| 共享作品状态或导航 | 切换、真实链接、刷新、深链接和返回 |
| 动效与背景 | 实际运动、过渡、暂停、减弱动态和离屏恢复 |
| 对话框与检索 | 键盘、非空输入、关闭焦点和无结果状态 |
| 图表与计算 | 独立计算、边界、负值、输入端点、舍入与图文同步 |
| 编辑与导出 | 修改内容、导出重开及生成模块只挂载一次 |
| 明确要求某设备版本不变 | 对照受影响的源文件、布局或截图；按风险选取 |

## 实际页面审查

在可用的本地或托管预览中查看页面，操作关键路径并留少量能说明结果的截图。截图前等待相关媒体、字体和场景稳定；不要用加载中画面判断最终设计。

第三者视角关注：

1. 初次访问能否迅速理解身份、方向和作品入口？
2. 作品是否说明真实贡献，证据是否能看清？
3. 同一内容是否反复出现，是否需要多余面板或步骤？
4. 景观是否抢夺文字，运动是否妨碍阅读和操作？
5. 模态框、图表与返回路径是否可靠？

检查正常动态与静态/暂停状态的实际画面。自动断言可补充状态检查，但无法证明审美或可见性完整。

大型改版、复杂状态链或事实敏感页面可交给独立审查者。给其候选页面和原始材料，让其自行检查；不能只让其复述作者的预期结论。

## 修复与结束

发现问题先确定其具体触发状态与影响，修改对应实现后复测。只有修复影响相邻行为或必需发布关卡时才扩大检查范围。

完成条件：

- 本次要求均有对应实现；事实和公开范围正确。
- 主要阅读与操作路径可用；实际画面没有阻断阅读或操作的缺陷。
- 用户要求保留的范围已按实际风险验证。
- 没有剩余阻断问题；交付形态符合本次请求。

审美建议按对当前页面的影响排序。完成必要修复后交付，不把每条可选建议继续扩张成新的功能。

## 交付说明

简短说明主要变化、使用入口、实际验证与材料性限制。可提供一张有代表性的截图或审查记录，不必列出所有测试计数、代码文件和历史版本。

制作记录保留足够复用的决定和证据；小任务可在最终回复中说明。测试与设计资料是否进入代码仓库依现有项目规范；部署归档只装需要提供服务的构建产物与元数据。
